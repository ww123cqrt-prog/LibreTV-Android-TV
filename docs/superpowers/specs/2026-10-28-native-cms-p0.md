# 原生 Apple CMS P0

用户已明确选择先把 Apple CMS 搜索和详情解析放到 Kotlin 客户端，再处理确实需要代理的特殊源。本文件记录该已授权范围，采用独立仓库和独立包验证。

此文为初版实现范围的历史记录，不能理解为用户要求删除推荐首页。后续用户已要求补齐，推荐条目由 2026-10-28-recommendation-home.md 覆盖。

## 范围

- 基线：DpadTV v1.2.0，4dd04cc4e394c808980aeebb2495a5af8d134e74；LibreTV v2.21.1，29cbeb3d37b4876f909a0354087a3531af0447f6。
- applicationId 为 local.libretv.standalone.tv，应用名 LibreTV 独立版 P0；不覆盖 com.dpadtv.client。
- Kotlin 直连用户现有的九个普通 Apple CMS 源，复用原搜索结果封面墙、详情选集、切换来源、Media3、缓存与历史。
- 移植 JSON 边界解析、多线路优先 m3u8、简介直链兜底、相关性及季数过滤、去重、最多五页搜索与逐源失败信息。
- 初始化后直接显示搜索入口，用户不配置服务器或密码。图片直接请求；本轮不启动任何 HTTP 服务，也不调用 Windows 后端。
- 没有证据需要代理的功能不提前实现；推荐、直播解析、特殊 HTML 抓取、视频代理、自动换源、APK 内更新明确记为未覆盖。
- 片源导入保留原有文本、文件、网址入口；种子只在新包首次运行导入，用户清空后不自动恢复。

## 选择

原生移植是本轮选择。内嵌完整 Next.js 暂不实施；代理仅在直连失败证据明确后按源处理。保留原版与 Windows 正式环境，不修改系统，不安装系统自启动组件。

## 验证

先以 v2.21.1 实际 TypeScript 函数生成固定预期，确认 Kotlin 测试失败再实现。用本机 HTTP 测试验证真实请求路径、分页和单源失败不会污染成功结果。随后通过单独的测试 APK 在 N5 Pro 执行同一生产客户端，再使用新 App UI 实测搜索、选集和播放，记录每个源的结果、耗时、内存和原包版本。

证明范围分开：源代码与请求观测可验证没有后端依赖；物理关闭 Windows 的最终验收需要用户配合，未做时不写为通过。测试 APK 和生产 APK 不包含电脑服务凭据。首次安装使用独立稳定签名，签名私钥仅保存在本地并排除源码交付。

## 完成条件

交付可并存的 APK、完整对应源码、覆盖对照和实机证据。结论为普通 CMS 核心链路的可行性，不把 P0 称为完整 LibreTV。无法直连的源保留分类错误，不通过关闭 TLS 验证或伪造成功处理。
