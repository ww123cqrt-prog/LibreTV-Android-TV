# LibreTV 0.1.12：导航、设置与收藏

2026-11-08。版本为 0.1.12 / 13，包名继续使用 `local.libretv.standalone.tv`，显示名称仍为 LibreTV。

## 操作变化

- 电影、剧集、综艺、搜索、收藏、继续、片源与设置共用顶部导航。搜索和设置使用放大镜、齿轮图标，保留可访问名称。
- 一级页面的内容区按返回，将焦点移到顶部当前栏目，并保留内容。焦点已在顶部时再按返回，回到桌面。弹窗、软键盘和详情等子页面先关闭当前层。
- 设置页采用六张卡片。播放设置的名称与当前值分列显示，代替空格对齐的长文本。
- 播放操作栏在“选集”后提供星标收藏，再按一次取消。按整部影片／剧集保存，以片名和年份区分，同剧换集不会重复收藏。收藏操作保留播放器和暂停状态。
- 一级“收藏”位于“继续”左边。旧导航顺序只补入新入口。收藏海报仍搜索全部启用片源；从结果返回可回到收藏，长按海报可取消收藏。
- 解码、比例、倍速及播放设置共用电视选择框。列表高度由屏幕与选项数决定，长列表可上下滚动，返回取消。

旧历史缺少年份时，恢复集单会同步收藏身份。若已提前收藏，会将空年份条目迁入确认后的年份，保留已有的同年收藏。

收藏保存于应用私有配置，也进入原生备份的可选字段。原 v1 备份仍可读取。恢复确认会显示收藏数量；恢复会替换当前收藏。签名、权限、SDK 要求与 0.1.11 保持一致，通过同签名覆盖更新。

## 本机验证

74 项 JVM 测试通过，包括收藏备份往返、旧备份兼容和损坏收藏拒绝恢复。主 APK、测试 APK 编译通过。

使用独立的只读 TV 模拟器副本：`PeachTV_API34_1080p`，Android 14 / API 34，1920 × 1080，序列号 `emulator-5560`。截图中的片源数量和片名是模拟器测试数据。

| 模拟器场景 | 实际验证 |
| --- | --- |
| `tv-navigation` | 图标入口、收藏位置、六张设置卡片可见、两步返回、遥控更改解码、旧导航补项；设置顶部进入片源按一级页面返回 |
| `tv-dialogs` | 解码与比例均有 3 个完整可见选项 |
| `tv-favorites` | 遥控添加／取消、换集不重复、保留播放器与暂停、搜索两个测试片源、返回收藏、进入备份 |
| `tv-favorites-history` | 旧历史延迟恢复年份，提前收藏后同步年份与星标，不重复增加 |
| `home-rankings` | 四个既有榜单、剧集分类范围、回退与缓存 |
| `history-next` | 继续观看后仍为同剧下一集，旧历史可恢复集单 |
| `prefetch-page` | 48 条追加到 96 条，保持原网格、焦点和滚动位置，无阻塞弹窗 |

同一导航用例在旧 APK 上因文字搜索按钮失败，新包通过。首轮测试没有考虑卡片缩放和窗口交接时序，已修正测试几何容差与焦点等待；这些测试问题没有当作产品缺陷。

Lint 任务完成，但报告没有清零：143 处 Media3 opt-in、2 处旧返回 API、1 处本机路径检查，以及 44 条警告。未将任务退出成功描述为零错误。该范围未包含播放器 API 的整体迁移。

## 投影仪边界

用户此前要求暂停投影仪操作。本轮没有连接 N5、安装 APK、发送按键或操作光源；原 DpadTV 也未操作。N5 的真实遥控与布局验收仍待用户恢复设备工作。

旧 APK 在模拟器中已能显示解码、比例的三项列表，未复现用户在 N5 上看到的单项显示。因此本轮确认了新选择框的模拟器布局，未宣称已查明 N5 的原始根因。

## 复测

构建沿用项目签名和已有工具链。只在可丢弃的 TV 模拟器上运行这些夹具；它们临时替换测试配置并在正常结束后恢复。

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest --console=plain
adb -s emulator-5560 shell am instrument -w -r -e mode regression -e case tv-navigation local.libretv.standalone.tv.test/com.dpadtv.client.NativeCmsInstrumentation
```

将 `tv-navigation` 替换为表中场景可分别复测。本轮构建日志、JSON 报告、原始截图和校验脚本保存在工作任务的 `work/libretv-ui-20261108/`。
