# 推荐首页恢复：0.1.1-p0 验收

日期：2026-10-28。坚果 N5 Pro / K981CN，Android 14 / API 34。

## 原因与修改

原版 DpadTV 的推荐列表请求 LibreTV `/api/douban`，封面请求服务端图片代理，电脑上的 LibreTV 再向豆瓣取数据。视频直接播放与推荐经过服务端是两条不同路径。

上一版 0.1.0-p0 只完成 Apple CMS 搜索、详情和点播可行性验证，主动绕过了现有推荐首页。推荐 UI 并未删除。这是实现范围收得过窄，不是已证实的设备能力限制。

0.1.1-p0 复用了原来的推荐 UI，首页、电影/剧集/综艺切换、点击海报搜索、搜索页热榜以及首页按钮排序均已接回。推荐列表直接请求 `movie.douban.com/j/search_subjects`；封面直接请求豆瓣图片 CDN，并传递上游使用的公开 Referer 与 User-Agent。不使用 Windows 服务、不引入 Next.js 或新代理，也不需要豆瓣账号。

## 实机结果

| 类别 | 列表条数 | 封面样本 | 含样本下载及完整解码耗时 |
| --- | --- | --- | --- |
| 电影 | 48 | 29729 字节，270×405，完整解码通过 | 1111 ms |
| 剧集 | 48 | 25757 字节，270×404，完整解码通过 | 1245 ms |
| 综艺 | 48 | 36399 字节，270×405，完整解码通过 | 843 ms |

测试 APK 调用生产 Api.douban / imageBytes，使用 BitmapFactory 完整解码并释放样本。三类合计 3244 ms，为单次样本，不是长期性能承诺。

原生界面显示了三类各 48 条的海报墙。使用标准遥控方向键在网格与分类工具栏之间移动，切换剧集、综艺成功。点击电影推荐“逃出布迪秀”后，Apple CMS 搜索返回 2 个片名分组、7 条来源结果。标题和热门排序由第三方上游返回，可能随时变化。

修复并实测两个日常交互问题：

- 热榜异步刷新只更新热榜容器，不再重建输入框。进入搜索后立即输入 `006`，三类热榜显示后文本仍为 `006`，输入焦点保持。
- 首次加载推荐前先建立可用首页。冷启动加载时按返回取消，仍保留电影、剧集、综艺、搜索等按钮，没有空白页和取消异常弹窗；可直接进入搜索。

JVM 测试从 36 增加到 40。新增四项先观测到失败，再实现通过；覆盖推荐直连分页/标签参数、公共 Referer、综艺归入 TV、评分映射、HTTP 错误和缺失 subjects 的错误传播。40/40 通过，主 APK 和测试 APK 构建成功。原有 CMS 解析/传输检查仍通过。

## 使用与交付边界

重新打开 `LibreTV 独立版 P0`，默认进入推荐海报首页。上方向键回工具栏，左右选电影/剧集/综艺/搜索，OK 确认；点海报会搜索片源，再进入详情选集播放。

这是首页功能补齐，不是完整 LibreTV 完工。直播列表解析、自动换源、特殊源代理、订阅自动刷新及应用内更新仍未完成；真正关闭 Windows、重启投影仪和长时间稳定性仍待验收。原生直连可能受到豆瓣限流或网络可达性影响，失败会显示错误并提供搜索入口，不会悄悄改走公共代理。

APK 与对应源码使用独立版本文件名交付；源码包含 DpadTV GPL-3.0 与 LibreTV AGPL-3.0 文本、修改说明、构建与签名初始化步骤。私钥不打入源码包，后续兼容升级需保留工程 `.signing`。
