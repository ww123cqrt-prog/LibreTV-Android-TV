# LibreTV 0.1.6：播放中换源验收

## 结果与操作

0.1.6 / 7 已同签名覆盖安装至坚果 N5 Pro（K981CN，Android 14 / API 34）。原版 DpadTV 保留。

播放时按下键，选择操作栏首项“换源”。App 查询全部启用片源，按精确片名和年份查找同片资源。来源详情验证后即可显示，其他来源继续补充；列表按详情响应耗时排序，补充时保留原选中项。选定新来源后保留集数顺序、时间位置及播放／暂停状态。

查询期间原视频保持播放状态，取消查询也不退出播放器。缺少当前集的来源会提示并保留原播放。切换时沿用同一个 Media3 实例；新来源在首帧前报错或 15 秒内没有首帧，尝试恢复原列表及断点。首次成功渲染之后，该来源正常接管播放。

## 验证范围

本机执行 `:app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest` 成功，56 项 JVM 测试全部通过。其中新增 6 项覆盖旧历史标题／集数还原、翻拍年份及解说／季名隔离。

测试 APK 内的短片由本机 FFmpeg `testsrc2` 生成，时长 12 秒。探针在设备内临时提供 HTTP 短片，只监听 `127.0.0.1`。测试调用生产播放器的换源方法，复用同一个 Media3 实例。测试结束后关闭监听并移除探针自己的缓存；生产 APK 不含短片、探针或测试服务。

N5 首次受控测试时系统屏保仍在最前，暂停换源未渲染首帧，测试失败。确认前台为 DreamActivity 后，只用普通返回键退出屏保，再验证通过。没有修改屏保或电源设置。最终构建重复验证通过。

真实影片样本为《给阿嬷的情书》。模拟器从非凡换到光速后显示实际影片画面并继续播放。N5 从非凡换到光速时保持暂停在 0:32，总时长分别为 119:50、118:37；换源后有实际画面。最终构建从历史继续播放，再换回非凡，显示第 1/2 集、实际影片画面及 3:29 / 119:50。查询期间进度正常推进，不是从查询开始时的旧位置续播。

渐进列表在两台设备均显示“继续查找中”及已可选择的来源；模拟器验证取消列表后原视频继续播放。列表采样耗时包含 UI dump 与截图开销，不作为接口性能基准。列表中的毫秒数仅测量详情请求，不代表视频带宽。

更新前后私有配置文件字节一致。此次实测后，9 个片源内容不变；原有 5 条历史及 5 项进度均保留，真实换源正常新增一条来源记录，总计各 6 条。原版 DpadTV 的版本及安装／更新时间不变，`stay_on_while_plugged_in` 读回仍为 0。

另观察到历史页从播放器返回后仍显示进入播放前的时间。直接读取存储，非凡和光速的最新进度分别为 451954 ms、206470 ms，已正确保存。历史页即时刷新列为下一步处理，不影响已保存的续播数据。

## 数据路径与边界

来源搜索和详情由投影仪中的 Kotlin 代码直连 Apple CMS 接口；Media3 直连选中的媒体地址。此次功能没有使用 Windows LibreTV、ADB reverse、本地代理或 Node.js 运行时。

来源的集数按播放列表顺序对应。不同来源若有预告、番外、片头或剪辑差异，画面可能无法按相同秒数对齐。旧历史缺少来源及年份信息时，按原标题恢复片名和集数，在候选中显示年份供确认；没有迁移或重写历史格式。

首帧错误恢复已实际触发。15 秒等待规则已实现，本轮未单独注入持续无首帧的故障；恢复仍要求原媒体地址可用。首次成功渲染后的网络故障不会自动换源，可再次手动选择。此次遥控流程使用 ADB 方向键注入，原装遥控器手感仍待用户体验。

关闭 Windows、投影仪完整重启、断网恢复及长时间连续播放的全链路验收仍待完成，不把本次短播放当作这些项目通过。直播、应用内更新已按用户要求取消。

```powershell
& $n5.Adb -s $n5.Serial shell am instrument -w -r -e mode switch-player local.libretv.standalone.tv.test/com.dpadtv.client.NativeCmsInstrumentation
```
